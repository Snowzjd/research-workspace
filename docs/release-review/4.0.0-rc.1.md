# 4.0.0-rc.1 source review

Status: the source snapshot is recorded on this branch for review. This document does not accept 4.0.0-rc.1 as a published release, a stable 4.0.0 release, or a replacement for an installed 3.2.3 build. No tag, GitHub Release, binary upload, shortcut change, or merge is part of this commit.

Two evidence classes are kept apart below. Handoff-reported statements were supplied with the task and were not rerun here. Personally observed statements were checked in this cloud workspace on 2026-11-21.

### Electron maintenance and security

Observed from Electron's own release pages on 2026-11-21:

- [Electron 32.2.0](https://releases.electronjs.org/release/v32.2.0) was released 2024-10-10 with Chromium 128.0.6613.178, Node.js 20.18.0, and V8 12.8.374.36. That matches `THIRD-PARTY-NOTICES.md`.
- [The Electron schedule](https://releases.electronjs.org/schedule) gives Electron 32 an end-of-life date of 2025-03-03. [Electron's support policy](https://www.electronjs.org/docs/latest/tutorial/electron-timelines) supports the latest three stable majors, and only the newest minor of each.
- [Electron 32.3.3](https://releases.electronjs.org/release/v32.3.3), released 2025-03-03, is the last 32.x release. Its notes say Electron 32 has reached end of support and name security backports, including CVE-2025-0445 and CVE-2025-0998, that 32.2.0 does not contain. Chromium there is 128.0.6613.186 and Node.js is 20.18.1.
- The [stable channel page](https://releases.electronjs.org/?channel=stable) listed 45.4.1, 44.11.5, and 43.8.12 as the current supported lines, released 2026-11-19.

`npm audit --package-lock-only` in `desktop/` reported 2 high-severity groups: the `electron` package at versions `<=42.11.15` (32.2.0 is inside that range), with a long list of GitHub advisories, and `extract-zip` symlink extraction advisories. The audit's suggested repair is `electron@45.4.1`, a breaking change. This commit does not apply it, does not change sandbox, context isolation, navigation, or webview settings, and does not treat every advisory as proven against this candidate. Several named issues are platform-specific or depend on features the candidate window turns off (`webviewTag` is false when `fullCandidate` is true, and the candidate window sets `sandbox: true`, `contextIsolation: true`, and `nodeIntegration: false`). Applicability was not exploited or retested. `extract-zip` is the Electron downloader's unpacker, not a file the packer copies into `resources/app`.

`pack-full.mjs` can set the icon and version strings with `RW_RCEDIT`. It does not call an Authenticode signing tool. The unsigned state reported for the Windows runtime is consistent with this source and was not rechecked on an executable.

## Publishing blockers and owner decisions

These are not patched in this commit. A code or notice change against the tested snapshot needs its own manifest and invalidates the existing Windows binary acceptance until that tree is rebuilt and retested.

1. First-party license. The metadata says MIT, and the repository has no license file and no named copyright holder. Adding one requires the owner to choose the holder and the text.
2. Electron 32.2.0 is outside upstream support, lacks the 32.3.3 security backports, and is inside the vulnerable range reported by npm audit. Whether to stay on the tested runtime for this RC or move to a supported Electron is an owner decision. This branch does not upgrade it.
3. Signing, SmartScreen behavior, and the distribution channel are still open. The source packer does not sign.
4. The metadata-only guard for one project id and `G:\TPMS` is machine-specific. Keeping it preserves the tested candidate. It does not describe any other method.
5. `README.md` still points readers at `releases/latest` and the daily AppData directory. `FULL-CANDIDATE.md` is the RC note. The README was not rewritten.
6. OpenAPI `info.version` remains `3.2.1` inside the candidate API document.
7. `THIRD-PARTY-NOTICES.md` does not mention marked or DOMPurify, which are embedded only in unpackaged `demo.html`.
8. Native Vault picker, real old-data import, cross-device use, and the Windows commands listed above remain manual gates. The program ZIP named by the handoff was not in this workspace.
